## dbt-snowflake 1.12.1 - September 16, 2026

### Features

- Add beta support for the Snowflake `interactive_table` materialization, covering static and dynamic (auto-refreshing) interactive tables with `target_lag`, `cluster_by`, refresh/initialization warehouses, and in-place configuration changes via ALTER where Snowflake supports it ([#1780](https://github.com/dbt-labs/dbt-adapters/issues/1780))

### Fixes

- Ignore `change_tracking=false` for Iceberg tables instead of emitting invalid DDL, since Snowflake does not allow change tracking to be turned off for Iceberg tables ([#0](https://github.com/dbt-labs/dbt-adapters/issues/0))
- Fix cluster_by, target_lag, and snowflake_initialization_warehouse change detection for dynamic tables: none of the three were normalized before comparing, causing spurious no-op ALTER statements every run (LINEAR-prefix and case for cluster_by, unit for target_lag, case for the warehouse) -- interactive tables already had this fixed ([#](https://github.com/dbt-labs/dbt-adapters/issues/))
- Escape single quotes in identifiers interpolated into `SHOW ... LIKE` metadata queries for dynamic and interactive tables: a model whose name contained a quote terminated the SQL string literal early, so describing the relation failed or ran unintended SQL ([#](https://github.com/dbt-labs/dbt-adapters/issues/))
- Compare a dynamic table's refresh warehouse case-insensitively when detecting configuration changes: Snowflake folds unquoted warehouse names to upper case on readback, so a desired `my_wh` compared against a reported `MY_WH` was treated as a change and fired a spurious ALTER on every run ([#](https://github.com/dbt-labs/dbt-adapters/issues/))
- Strip double-quote delimiters from a warehouse name before comparing it case-insensitively during configuration-change detection: `SHOW` never echoes the quotes back, so a quoted `snowflake_warehouse`/`refresh_warehouse`/ `snowflake_initialization_warehouse` value never compared equal to its own readback and fired a spurious ALTER on every run ([#](https://github.com/dbt-labs/dbt-adapters/issues/))
- Treat a single-quoted string literal inside a clustering expression (e.g. `to_char(ts, 'MON')`) as case-sensitive data during configuration-change detection: the surrounding expression text was folded correctly, but a literal's exact case, and any `)`/`,` characters embedded inside it, previously corrupted the comparison and could cause an unnecessary full refresh on every run. Live-verified against Snowflake ([#](https://github.com/dbt-labs/dbt-adapters/issues/))
