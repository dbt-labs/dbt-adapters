## dbt-snowflake 1.13.0-b1 - November 04, 2026

### Features

- Add `snowflake_managed_iceberg_default` behavior flag. When enabled, Iceberg tables without an explicit `external_volume` emit `external_volume = 'SNOWFLAKE_MANAGED'` and suppress `base_location`, enabling Snowflake Horizon managed storage out of the box. Setting `external_volume = 'SNOWFLAKE_MANAGED'` explicitly in model config always suppresses `base_location` regardless of the flag. ([#1911](https://github.com/dbt-labs/dbt-adapters/issues/1911))

### Fixes

- Fix dbt clone for Iceberg tables by using CREATE ICEBERG TABLE syntax when source is an Iceberg table ([#1767](https://github.com/dbt-labs/dbt-adapters/issues/1767))
- Map values by column name rather than column position in the Snowflake `insert_overwrite` incremental strategy, so an enforced contract or a column appended by `on_schema_change` can no longer silently write values into the wrong columns. Three side effects, each matching how the other incremental strategies already behave: with the default `on_schema_change='ignore'`, a column added to the model is now dropped rather than failing on a column-count mismatch, and a renamed column now errors rather than writing into the old column; with `on_schema_change='append_new_columns'`, a column removed from the model is now set to null rather than failing on a column-count mismatch ([#1511](https://github.com/dbt-labs/dbt-adapters/issues/1511))
- Fix persist_docs and relation caching for dbt clone of Snowflake Iceberg tables, and drop an existing target when cloning between Iceberg and regular table formats ([#1767](https://github.com/dbt-labs/dbt-adapters/issues/1767))
- Emit change_tracking before copy grants, copy tags, row access policy and tag in Snowflake CREATE TABLE AS to match the documented clause order ([#2244](https://github.com/dbt-labs/dbt-adapters/issues/2244))
- Emit IGNORE GRANTS on Snowflake CREATE OR REPLACE for tables, views and clones when copy_grants is not true, preserving the no-copy default ahead of BCR-2433 ([#2261](https://github.com/dbt-labs/dbt-adapters/issues/2261))
- Keep NUMBER/DECIMAL precision and scale when creating Iceberg tables in a Glue catalog-linked database, instead of creating INT columns that round fractional values. Integer columns become DECIMAL(p,0), with precision from the query as in CTAS. Existing incremental tables keep INT until rebuilt with --full-refresh; until then, runs with on_schema_change set to fail or sync_all_columns error. ([#2165](https://github.com/dbt-labs/dbt-adapters/issues/2165))
- Quote unique_key, merge_update_columns and the microbatch event_time column for incremental models in a Glue catalog-linked database, whose lowercase columns an unquoted name could not match ([#1473](https://github.com/dbt-labs/dbt-adapters/issues/1473))

### Under the Hood

- Bump the upper bound of snowflake-connector-python from <5.0.0 to <6.0.0 ([#NA](https://github.com/dbt-labs/dbt-adapters/issues/NA))
- Write NUMBER(p,s) instead of DECIMAL(p,s) for number columns of Iceberg tables in a Glue catalog-linked database, as dbt Fusion does. The column type Snowflake creates is the same. ([#2165](https://github.com/dbt-labs/dbt-adapters/issues/2165))
